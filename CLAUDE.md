# buildhost

Universal package registry server. Upload artifacts once, download in any format.

This file is an INDEX: what exists, the invariants one line each, and where the depth lives. Depth goes in `docs/`, never back into a bullet here. The `claude-md-budget` plugin enforces it: over 40,000 characters, or within 2.5% of it. `docs/claude-md-budget.md` -- what the guard measures, and what an oversized instruction file costs on every request.

## Build

```bash
go-toolchain --generate 0af38e6ba5f6
```

This runs mod tidy, generate, vet, tests with coverage, and builds the binary. Do not use a bare `go` command. The `--generate <hash>` flag is go-toolchain's approval gate over the repo's `//go:generate` directives. It is REQUIRED here. Every generated input is gitignored, so a fresh clone without generate fails to compile. Building therefore needs npm as well as Go. go-toolchain prints the current hash when this one is stale. Update it here and in `.github/workflows/ci.yml` whenever a directive changes.

Generated by a `//go:generate` directive, and gitignored: `internal/api/gen_project_name.go` (go-regex-compiler), `internal/repackage/cacerts/ca-certificates.crt` (fetched), `internal/admin/static/*.js` (TypeScript in `internal/admin/frontend/src/`). Generated and COMMITTED: `internal/db/*.sql.go` (sqlc) -- editing a query in `internal/db/queries/*.sql` puts its regenerated Go in the same diff. Which directive lives where, and how to re-run sqlc: `docs/code-generation.md`.

## Project structure

- `cmd/buildhost/` -- CLI entrypoint (cobra, one subcommand per file, self-registering via init()). Backend imports (backend_*.go) trigger init() registration for each handler package.
- `internal/server/` -- HTTP server, global middleware chain (auth, inflight tracking, security headers, logging, recovery).
- `internal/api/` -- REST API handlers for projects, releases, artifacts, publish and tokens. Each file registers its own routes. Depth: `docs/rest-api.md`, `docs/uploads.md` (fan-out and hash-reference uploads).
- `internal/static/` -- the ONE download endpoint, `static.{domain}/file`. Every format handler redirects here. Depth: `docs/http/static-endpoint.md`.
- `internal/dl/` -- `dl.{domain}/{project}` version/branch resolution, redirecting to static. Depth: `docs/http/dl-redirects.md`.
- `internal/apt/` -- APT repository on `apt.{domain}`. Depth: `docs/formats/apt.md`.
- `internal/brew/` -- Homebrew formulas and the generated, cloneable tap (dumb + smart HTTP, persistent per-lineage git history). Depth: `docs/formats/brew-tap.md`.
- `internal/npm/` -- npm registry on `npm.{domain}/@buildhost/{project}`. Depth: `docs/formats/npm.md`, `docs/npm-packument-manifest-cache.md`.
- `internal/oci/` -- OCI distribution, read + write (`docker pull`/`docker push`). Depth: `docs/formats/oci.md`.
- `internal/goproxy/` -- Go module proxy on `goproxy.{domain}`, replacing Athens. Fetches over HTTP (no `go`/`git` subprocess) and caches module zips as blobs. Depth: `docs/formats/goproxy.md`.
- `internal/sites/` -- static site hosting, one deployment per branch. Depth: `docs/sites.md`, `docs/site-archives.md`.
- `internal/llms/` -- public `/llms.txt` guide, on the apex and every service subdomain. Depth: `docs/http/routing-and-auth.md`.
- `docs/routes.txt` -- the committed route table, rendered BY the program. Routes must register in `init()`, never inside `auth.OnReady()` (which fires only at server boot, hiding them from every enumeration). Both gates fail on drift. Depth: `docs/testing.md`.

## Key design decisions

- Versioning: auto-increment (default) or semver (opt-in per project).
- Git branch is a first-class field on releases, not just metadata.
- Apex `latest` resolves to the newest published release on the project's default branch, which buildhost learns from GitHub itself. A feature branch can never hijack it, and there is no fallback to newest-overall. Depth: `docs/apex-latest.md`.
- Repackaging and stripping happen on demand at download time. Only the original upload is stored. Every cached digest carries `repackage.TransformVersion` in its fingerprint. A change of that value refills the digest. A stale digest is a `brew install` checksum abort, and an apt "Hash Sum mismatch", for every project at once.
- Multi-platform fan-out happens at upload time, never at download time. One blob becomes N ordinary per-platform rows. Nothing stores `os=any`, and there is no download-time fallback. Only a NON-APE upload fans out. Depth: `docs/uploads.md`.
- ONE file that runs on several platforms, an APE, is ONE artifact row. Publish it with `PUT .../artifacts/ape?platforms=os/arch,...`. `artifact_platforms` holds the slots. Every covered platform folds to one static URL. A multi-platform claim without APE magic is rejected. The `cosmo`, `any` and `all` aliases on the `{os}/{arch}` route publish an APE the same one-row way, rather than a fan-out. Depth: `docs/multi-platform-artifacts.md`.
- A declared platform is checked against the bytes. A `windows/*` claim on an APE whose PE header is the one-section do-nothing stub is refused at ingest. Such a binary starts on Windows and exits 0 without a run. Depth: `docs/uploads.md`.
- Every download goes through `static.{domain}/file` -- one CDN-cacheable endpoint with sorted params, strong ETags and immutable headers. `v=latest` returns 400.
- Storage is content-addressed with SHA-256, zstd-compressed and deduplicated. The compressor window bounds per-request memory, and the artifact size does not. Depth: `docs/storage.md`.
- Auth is Bearer, Basic or a query param, and all of them resolve to one token system. The scopes are `read`, `write` and `share`. Depth: `docs/security/tokens-and-links.md`.
- OIDC auto-provisioning is WRITE-ONLY. A read never materializes a project. Depth: `docs/security/oidc.md`.
- A project name is slash-namespaced and nests to any depth. Only the deb package name folds `/` and `_` to `-` (`repackage.DebPackageName`), because the Debian grammar forbids them. Depth: `docs/project-names.md`.
- Project auth is enforced ONCE, in `requireProject`. Handlers never check auth.
- A backend self-registers its routes in `init()`. To add a backend means to add files, never to edit an existing one. `auth.OnReady` wires handler deps only -- a route registered there is invisible to `buildhost routes` and to the PR route diff. Config-dependent patterns go through `auth.OnSiteDomain`, which route listing also runs. `internal/routescheck` fails on any route that appears only after `auth.Init`. Depth: `docs/http/routing-and-auth.md`.
- Draft releases (`releases.draft`) record INTENT, so retention cannot sweep a deliberate draft as an abandoned upload. Depth: `docs/apex-latest.md`.
- A docker-pushed release is OCI-only. It is gated out of apt, brew, npm and `/static`. A push mounts any blob storage already holds under a project the caller can read. An image built `FROM` a published base therefore never re-uploads that base. A published layer is always zstd, and there is no algorithm input. A consumer therefore needs an OCI-aware puller. Depth: `docs/formats/oci.md`.
- Static sites are stored as an indexed archive, one deployment per branch, replaced atomically. Depth: `docs/sites.md`.
- The Go module proxy never answers a failure of ITS OWN credential with 404. At the protocol level a 404 means the module does not exist. `go mod download` then reports a missing module, and the reader hunts a typo instead of the credential. That case is a 403. Every other case is a 502 or a 404, by classified cause. The CALLER's missing access is the opposite. It IS a 404, identical to a genuine absence, because a 401 or 403 confirms that a private module exists. Readiness is its own check, because a credential-less proxy serves every public module and no private one while it looks healthy. Depth: `docs/formats/goproxy.md`.

## Publishing from CI (.github/actions)

- Every publish registers a **GitHub Deployment** in the calling repo, and a failure is RED -- there is no opt-out. Depth: `docs/github-deployments.md`.
- **`buildhost-docker-push`** pushes an OCI layout in chunks (what `docker push` cannot do through a body-capped proxy) and records what was stored. It owns getting a CLI that can: download, else build from source. No caller handles a CLI.
- **Logging docker in is buildhost's job, never a caller's, and never a bare CLI command.** Actions do it inside their own steps, from the one shared `.github/actions/lib/docker-login.sh`: `buildhost-publish-docker` (before the build and the pull-back) and **`buildhost-docker-pull`** (fetch published images, e.g. into a nested daemon). There is no `docker-login` CLI subcommand, no login-only action, and no other supported path -- exposing one puts the credential back in a caller's hands.
- **`buildhost-download`** fetches one artifact from `dl`. With `required: 'false'` it reports a miss as an output instead of a failure, which is what makes that fallback expressible.
- Every publish posts a **storage record** to the org's artifact metadata API. That happens inside the publish step itself, rather than as a separate step. Retention retracts what it evicts. A failure is RED. Depth: `docs/artifact-storage-records.md`.

## Running

`buildhost bootstrap` mints the initial admin token. `buildhost routes` prints the route table. `buildhost serve` runs the server, and dispatches by the first label of the request Host. Depth: `docs/running.md`, which covers env vars, the admin port, telemetry, OIDC policy setup, and the optional site domain.

Deployment, graceful shutdown and the rolling-update contract: `docs/deploy-and-updates.md` -- including the invariant that two versions must never share the service alias.

## Testing

An assertion lives in a dats suite under `test/dats/`, never in a workflow step. A step installs dats and invokes one suite with `--no-sandbox`. These suites need the host's curl, jq or brew, and the runner's fallback sandbox image has none of them. A suite that needs nothing but the checkout or a built binary lives in `dats/`, which `go-toolchain` runs sandboxed on every build. A check that needs a program, such as an octokit fake or a browser, is a node test under `test/actions/` that a suite invokes. Depth: `docs/testing.md`.

CI runs the shipped fat APE. An APE starts through its own shell trampoline. A bash `run:` step does that implicitly. Node's `spawn` does not, so pass the path to `sh`. The image carries one static busybox `/bin/sh`. The image's entrypoint is a shebang launcher, never the APE itself. A bare exec of an APE is exit 126. A rolling update runs whatever entrypoint the container it replaces recorded. Depth: `docs/deploy-and-updates.md`. A test that needs a real ELF compiles its own fixture.

`go-toolchain` runs all tests. An inline `script:` in any action or workflow may not carry two or more consecutive `//` comment lines. The typescript action refuses to run such a script. CI therefore checks every file up front, rather than let a seldom-triggered action break in a consumer repo.

Several end-to-end jobs in `ci.yml` are NOT part of that run. They guard defects that a unit test structurally cannot catch. They are `synthesized-image-e2e`, `homebrew-tap-e2e`, `container-healthcheck`, `apt-install-e2e` and `upload-artifact-action-e2e`. Depth: `docs/testing.md`.

step installs dats and invokes one with `--no-sandbox`. These suites need the

through a shell. Every image entrypoint test then passes whatever the image
ships, so those suites refuse to run when one is registered.

## Security

Reviewed items and intentional trade-offs live in `docs/security/`:

- `docs/security/reviewed-items.md` -- the reviewed-and-accepted list (rate limiting, TLS termination, admin auth, site headers, public sites under private projects, ...).
- `docs/security/oidc.md` -- the whole OIDC trust model: auto-provisioning, the org/event allowlists, audience handling, and repo-identity pinning against renamed or resurrected repositories.
- `docs/security/tokens-and-links.md` -- token scopes and the stateless, artifact-bound temporary download links.
- `docs/security/github-signin.md` -- browser sign-in with GitHub, per-repo authorization, the cross-domain handoff, and primary-domain scoping.
