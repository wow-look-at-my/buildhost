# Code generation

Extracted verbatim from CLAUDE.md, no wording changed.

Every generated input is gitignored and produced by a `//go:generate` directive,
so `go-toolchain --generate <hash>` (see the Build section of CLAUDE.md) is the
one command that materializes all of them.

`internal/api/gen_project_name.go` is generated by
[go-regex-compiler](https://github.com/wow-look-at-my/go-regex-compiler). The
`go:generate` directive lives in `internal/api/projects.go`. The embedded CA
bundle (`internal/repackage/cacerts/ca-certificates.crt`) is fetched by the
directive in `internal/repackage/oci.go`. The admin dashboard's JS
(`internal/admin/static/*.js`) is compiled from TypeScript by the directive in
`internal/admin/admin.go` (`scripts/build-admin-frontend.sh`); it is embedded
file-by-file so a skipped generate is a compile error rather than a blank
dashboard.

Database query code in `internal/db/*.sql.go` is generated by
[sqlc](https://sqlc.dev/). Config is in `sqlc.yaml`. To regenerate after editing
queries in `internal/db/queries/`:

```bash
sqlc generate
```

## Why the approval hash is required

The `--generate <hash>` flag is go-toolchain's approval gate over the repo's
`//go:generate` directives and is REQUIRED here: the generated regex matchers,
sqlc code, the embedded CA bundle and the admin dashboard's JS are all gitignored
build inputs, so a fresh clone without generate fails to compile (`undefined:
validProjectNameRegex`, `pattern cacerts/ca-certificates.crt: no matching files
found`, `pattern static/app.js: no matching files found`). Building therefore
needs npm as well as Go. go-toolchain prints the current hash if this one is
stale; update it in CLAUDE.md and in `.github/workflows/ci.yml` whenever a
directive changes.

## The admin frontend

The dashboard's browser code is TypeScript in `internal/admin/frontend/src/`; the
`internal/admin/static/*.js` it compiles to are gitignored build inputs generated
by `scripts/build-admin-frontend.sh` (a `//go:generate` directive), so building
needs npm. Never commit the JS -- a committed copy is what drifted from its source
for months. CI enforces it: after running generate it fails if a TRACKED file
changed, and separately if any tracked file is gitignored build output. Depth:
`docs/admin-frontend.md`, `docs/no-committed-build-artifacts.md` (why it went
unnoticed, and the checks).
