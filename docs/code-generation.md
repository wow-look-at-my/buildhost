# Code generation

Extracted verbatim from CLAUDE.md, no wording changed.

Every generated input is gitignored and produced by a `//go:generate` directive, so `go-toolchain --generate <hash>` (see the Build section of CLAUDE.md) is the one command that materializes all of them.

`internal/api/gen_project_name.go` is generated by [go-regex-compiler](https://github.com/wow-look-at-my/go-regex-compiler). The `go:generate` directive lives in `internal/api/projects.go`. The embedded CA bundle (`internal/repackage/cacerts/ca-certificates.crt`) is fetched by the directive in `internal/repackage/oci.go`. The directive in `internal/admin/admin.go` compiles the admin dashboard's JS (`internal/admin/static/*.js`) from TypeScript, through `scripts/build-admin-frontend.sh`. The embed names each file. A skipped generate is therefore a compile error instead of a blank dashboard.

Database query code in `internal/db/*.sql.go` is generated by [sqlc](https://sqlc.dev/). Config is in `sqlc.yaml`. To regenerate after editing queries in `internal/db/queries/`:

```bash
sqlc generate
```

## Why the approval hash is required

The `--generate <hash>` flag is go-toolchain's approval gate over the repo's `//go:generate` directives. It is REQUIRED here. The generated regex matchers, the sqlc code, the embedded CA bundle and the admin dashboard's JS are all gitignored build inputs. A fresh clone without generate therefore fails to compile (`undefined: validProjectNameRegex`, `pattern cacerts/ca-certificates.crt: no matching files found`, `pattern static/app.js: no matching files found`). Building needs npm as well as Go. go-toolchain prints the current hash when this one is stale. Update it in CLAUDE.md and in `.github/workflows/ci.yml` when a directive changes.

## The admin frontend

The dashboard's browser code is TypeScript in `internal/admin/frontend/src/`. It compiles to `internal/admin/static/*.js`, which are gitignored build inputs. A `//go:generate` directive produces them through `scripts/build-admin-frontend.sh`, so building needs npm. Never commit the JS. A committed copy is what drifted from its source for months. CI enforces that. After it runs generate it fails when a TRACKED file changed. It fails separately when a tracked file is gitignored build output. Depth: `docs/admin-frontend.md` and `docs/no-committed-build-artifacts.md`, which cover why the drift went unnoticed and what the checks are.
